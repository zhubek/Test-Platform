# Internationalization (en / ru / kk)

The app is tri-lingual today (**English, Russian, Kazakh**) but authored content is moving to a dynamic per-project language set — see [i18n-rework.md](./i18n-rework.md). There are two distinct localization mechanisms — keep them separate in your head:

1. **UI chrome** (button labels, headings, table columns) → `t("some.key")` from a flat key map. Fixed `en / ru / kk` codes, ships with the app.
2. **Authored content** (test names, profession descriptions, choice text) → the `Localized` map (a dynamic `Record<string, string>` keyed by BCP-47 code, e.g. `{ en, ru, kk }`).

> Kazakh is `kk` (ISO 639-1), **not** `kz` (that is the country code). The old `kz` key was renamed to `kk` across code and stored data.

## UI chrome: `i18n.ts` + `t()`

`src/lib/i18n.ts` exports:

- `type Locale = "en" | "ru" | "kk"`
- a `translations` object shaped `Record<Locale, Record<string, string>>` — a **flat key→string map** per language (`en: { ... }`, `ru: { ... }`, `kk: {}`).
- `function t(locale, key)` → returns `translations[locale][key]`, falling back to `translations.en[key]`, then to the raw `key` if missing.

Notes:

- Keys are **dotted strings**, e.g. `"cm.methodic.heading"`, `"professionDetail.tabs.description"`, `"cm.methodic.tab.output"`.
- The `kk` block is largely empty and **falls back to English** — that's by design, not a bug.
- Because missing keys return the key itself, a page won't crash on an absent translation; it'll just show the key. Add the key to both `en` and `ru` blocks.
- The map is large and shared with the app this project was forked from, so many `cm.methodic.*`, `professionDetail.*`, and `professions.*` keys already exist.

### Adding a key

Add the same key to **both** the `en` and `ru` blocks (kk optional). Duplicate keys inside one block are a TypeScript object-literal error, so check it isn't already present before adding.

## Authored content: `Localized`, `localize()`, `l()`

`src/lib/localized.ts`:

```ts
// Dynamic map keyed by BCP-47 code — any per-project language set, not a fixed shape.
export type Localized = Record<string, string>;

// Pick the locale's string, falling back through the project default, then en, then any present key.
export function localize(field: Localized | null | undefined, locale: string, projectDefault?: string): string;

// Legacy positional constructor (en, ru?, kk?) — kept for existing call sites.
export function l(en: string, ru = "", kk = ""): Localized {
  return { en, ru, kk };
}

// Forward-looking constructor anchored on a project's default language code.
export function loc(defaultCode: string, text: string, more: Record<string, string> = {}): Localized {
  return { [defaultCode]: text, ...more };
}
```

Use `Localized` for anything a content author types per language. Use `l("Hello", "Привет")` as a concise constructor in seed/mock data; prefer `loc(projectDefault, "Hello")` in new code that knows the project's default language.

## The locale context

`src/lib/locale-context.tsx` provides `LocaleProvider` + `useLocale()`:

```ts
const { locale, setLocale, t } = useLocale();
```

- `locale` — current `Locale`.
- `setLocale(next)` — switches language and persists it to the `profwise_locale` cookie (1-year max-age).
- `t(key)` — bound translator (`= (key) => translate(locale, key)`).

The topbars (`admin-topbar`, `public-topbar`, `orgadmin-topbar`) all render a KZ/RU/EN switch that calls `setLocale`.

## Localized input components

For editing `Localized` values there are dedicated inputs — see [components.md](./components.md):

- `localized-input.tsx` — single-line, with a KZ/RU/EN language switch and a missing-translation dot.
- `localized-textarea.tsx` — multi-line version.

The Catalogs feature keeps its **own** teal-styled copies of these under `src/app/(admin)/admin/catalogs/_components/` (they respect a passed `className`, unlike the shadcn-styled top-level versions).

## Common patterns

- Render authored content: `localize(profession.name, locale)`.
- Render UI chrome: `t("cm.methodic.col.title")`.
- A localized field with empty ru/kz still renders English everywhere — the amber dot on the localized inputs flags which languages are still blank.
